# 本地应用演进：性能与断网基线设计

日期：2026-11-13。对应源码：MindNotes Pro `6.0.0-beta.12`。

用户已确认总体路线：保留 Windows 桌面应用，后端内置，断网可以使用笔记、截图及导入的本地资料；没有明确的单点性能问题，先建立启动、书写、保存与检索基线。离线要求是断网可用，现有在线网页阅读入口保留。

## 目标与阶段

最终结构为 React 界面、Electron 原生能力与本地应用服务、后台任务、SQLite 和受管理的资料文件。应用安装后独立运行，不要求用户安装 Node、数据库或另行启动服务器。实时指针采样和预览留在渲染层，完成的手势与编辑通过现有受限 IPC 保存。

本设计只覆盖第一阶段：建立可重复的性能测量、离线功能回归和结果比较。后续分别整理本地服务边界、增加一种本地资料格式的完整离线闭环、按测量结果实施性能优化。第一阶段不实现资料阅读器，不迁移存储，不增加 HTTP 服务，不修改绘制行为，不调整现有耐久保存策略。

## 现状依据

- `src/AppWrapper.tsx` 按运行环境懒加载悬浮工具条、屏幕层、笔记库、介绍页与兼容白板。
- 打包桌面壳使用 `loadFile`；字体与主要前端资源随包提供。网页浏览区仅接受 HTTP(S)，原文没有受管理的离线副本。
- 屏幕笔记的 SQLite worker 使用 WAL 和 `synchronous=FULL`；网页笔记使用原子 JSON 保存与 `.previous` 恢复；旧白板使用独立 v5 IndexedDB。
- `electron/performance.screen.mjs` 有单次生成数据测量，现有 `benchmark/` 主要针对旧白板。它们不提供完整的 v6 分布统计或桌面启动/帧基线。
- 历史 beta.12 测量不作为新工具的运行结果，也不证明当前机器上的 Windows 原生或实笔表现。

## 交付结构

新增工具置于 `benchmark/local/`，测试与工具共置，生成报告、临时库与日志置于 `tmp/local-baseline-20261113/` 或显式指定的工作区内任务目录。保留现有白板 benchmark 与验收脚本。

1. `report.mjs` 与 `report.test.mjs`：统计、结果结构验证、兼容性检查和回归比较。使用 Node 内置测试运行器。
2. `fixtures.mjs`：确定性的屏幕笔迹、笔记摘要和有效 PNG 数据，只生成测试数据。
3. `run-storage.mjs`：当前编译模块的 SQLite/网页 JSON 保存、检索、导入导出与重启读取测量，自动创建和清理隔离数据目录。
4. `run-desktop.mjs`：通过 Playwright 启动真实 Electron，测量启动、工具条、库界面、程序化书写、帧采样和进程资源；支持显式指定 Windows 实际包。
5. `offline.spec.ts` 与独立 Playwright 配置：真实 Electron 下阻断外部 HTTP(S)，验证现有本地操作与重启后恢复。
6. `compare.mjs`：只比较同一运行器、环境指纹、数据集、测量版本与样本策略的报告。
7. `benchmark/local/README_CN.md`：运行方法、解释范围、Windows 同包执行和报告边界。

生产代码只在发现现有真实回归时进入另行评估的修复范围；基线工具优先通过应用现有公开桥与 UI 工作，不为测量增加生产后门。

## 报告合同

报告格式为 `mindnotes-pro.local-baseline`，`schemaVersion: 1`。每份报告包含：

- `generatedAt`、`runner`（`storage` 或 `desktop`）、`status`（`passed`、`failed` 或 `unavailable`）。
- `applicationVersion`、源码 Git HEAD 与工作树摘要；编译模块或实际包的 SHA256 身份。明确当前未提交源码存在。
- `environment`：平台、架构、OS 版本、Node/Electron/Chromium 版本、CPU 型号、逻辑处理器数、内存、测试数据所在文件系统类型、显示器/缩放信息（桌面可用时）。编译身份覆盖实际加载的传递模块与锁文件，实际包身份同时覆盖 exe 与 app.asar。
- `parameters`：预热次数、测量次数、笔迹/点/笔记规模、idle 时长、帧采样时长和测量语义版本。`fixture` 包含版本 `local-fixture-v1`、固定 seed `20261113` 以及生成数据的 SHA256；只比较这些字段一致的负载。
- `metrics`：每项 `unit`、`samples`、`count`、`min`、`p50`、`p95`、`max`；毫秒与字节等不同单位不混用。分位数使用 nearest-rank：排序后取 `ceil(p*n)-1`。
- `checks`：功能检查名称、状态和错误；`limitations`：该运行器不能证明的内容。

空样本、非有限值、负耗时、未完成检查不得产生可用于比较的成功报告。失败或不可用结果可以输出诊断报告，命令必须以非零状态退出。缺失 Windows 可见环境不能被自动标记为通过。报告不记录真实笔记内容或截图。

比较工具默认关注耗时和内存上升，阈值为相对基线增加 20%；阈值可显式指定为非负有限数。比较采用 p95，输出基线、当前值和变化比例。零基线对应零当前为不回归，零基线对应正当前为回归，禁止除零后静默通过。身份或参数不兼容、当前缺少任一基线指标、同名指标单位/语义不符、失败报告等退出码为 2；确认回归退出码为 1；兼容且未发现阈值以上回归退出码为 0。代码与包身份允许不同，机器和测量语义必须相同。不得删除指标或把失败检查移出报告以获得比较通过。

## 数据与统计策略

默认 1 次预热、5 次测量，命令可配置次数并验证范围；首次连接/数据库创建成本单独记录，稳态操作不与首次初始化混在同一指标。5 次样本的 nearest-rank p95 等于最大值，首份报告为探索基线，20% 变化仅为本轮观察。默认生成 1,000 条笔记、1,000 笔/160,000 点，笔记数允许选择 100、1,000、10,000，此规模只用于屏幕库；网页库另外受 2,000 页面、20 MB、20,000 批注限制。默认生成笔画每笔 160 点，单笔 8,000 点的预览场景使用独立初始状态，不能叠加至已经达到点数上限的草稿。

每次重复明确初始状态：导入使用新 ID 或清理后的库，恢复读取关闭并重新打开仓库，检索在数据持久化完成后测量，导出使用单独目标文件。使用固定种子/公式，不使用随机内容决定负载。应用原有备份大小和笔迹限制仍有效。

存储测量包括仓库初始化、草稿耐久回执、网页笔记 JSON 保存与重开、摘要检索、详情读取、备份导出与流式导入。读取返回值和数量必须核对，不能只等待 Promise 即算有效样本。记录 Node 进程内存是运行器/worker工作负载的资源观察，不冒充整个 Electron 应用内存。

## 桌面测量

桌面 runner 必须显式传入 `--allow-visible`，才允许显示悬浮窗口并执行 Playwright 指针操作；该参数用于操作协调，不是权限机制。默认不运行可见桌面。源码模式使用当前生产资产，实际包模式使用 `MINDNOTES_EXECUTABLE` 或 `--executable`。每次进程使用新的隔离数据目录，恢复检查复用同一测试目录。

- 启动：从调用启动函数到悬浮入口按钮可见且可操作，名称为 `launchToBubbleReadyMs`。这是新进程启动，不称为清空 OS 文件缓存后的冷启动。
- 展开：点击悬浮入口到工具条可见，库打开：命令触发到笔记库可交互。
- 书写：Playwright 生成确定性手势；`pointerCommandMs` 记录 pointerup 命令返回，`gestureToSavedMs` 另等待预期新增笔迹 ID/摘要出现在状态中且保存状态为 saved。不能把历史 saved 或 mouse.up 返回作为最新笔画已落盘。另外记录帧间隔和长任务；它们只能反映调度与界面压力，不能直接证明 GPU 绘制完成或物理笔到像素延迟。
- 帧观察：使用 requestAnimationFrame 与 PerformanceObserver，结束时停止观察器/计时器，限制样本数量。隐藏页面没有有效帧样本时报告不可用。
- 资源：使用 `app.getAppMetrics()` 的进程类别、内存与 CPU；在入口、书写后、打开库和指定 idle 后分别观察。默认短运行 idle 为 5 秒，持续使用验收可显式指定 900 秒，报告保留时长。

Windows 的混合 DPI、鼠标穿透、真实截图、锁睡拔屏与物理笔仍由现有发行验收完成。本阶段的生成笔迹不能替代这些验收。

## 离线回归

离线回归使用当前 Electron 生产资产或显式实际包，在进程启动参数中配置只拒绝、不转发请求的本机测试代理，并移除 loopback 直连绕过；应用就绪后再核对并配置所有测试 session 的外部 HTTP(S) 请求拒绝。测试代理由运行器以随机端口启动并关闭，无法连接或配置失败时测试失败。保留本地 app 文件读取和测试所需协议。不把 DevTools 的页面离线开关当整个应用已断网。这验证 Chromium session 在网络不可用时的业务行为，不证明系统所有进程绝无网络流量；物理断网仍属于目标机验收。

离线测试提供本机 HTTP canary 控制实验：先由 Node 证明它可响应，再从应用尝试同一地址，确认代理记录拒绝且 canary 没收到应用直连。懒创建的 `persist:mindnotes-pages` session 也必须被覆盖；只看到 `.invalid` 域名导航失败不足以证明阻断策略生效。

固定隔离数据先准备有效网页笔记、屏幕笔记与草稿，再验证：

1. 本地壳启动、工具条与屏幕层加载，无依赖外部资源才能显示的必需界面。
2. 程序化绘制、撤销/重做、草稿保存与重启恢复。
3. 本地笔记库读取、屏幕与已有网页笔记检索、编辑保存。
4. 通过现有可信桥执行备份导出/导入，核对恢复数据；原生对话框采用现有隔离测试方法，不访问真实文件路径。
5. 在线网页导航被阻断时显示现有错误提示，仍可返回本地库，已有笔记不被删除。

屏幕捕获的真实像素依赖目标 Windows 环境；现有 native capture fixture 启动真实的 PowerShell 桌面软件并使用 desktopCapturer，不是跨平台模拟截图。只有目标 Windows 可见环境可以执行这条截图流程；Linux 侧只能用生成 PNG 核对存储/备份，不把它标为捕获通过。新资料格式不在这一回归范围内。

## 错误、隔离与恢复

运行器只访问自己的生成目录；不得读取软件真实 userData。所有临时目录位于当前工作区，项目进程设置 `TEMP`、`TMP`、`TMPDIR`。运行结束先关闭应用/worker，再删除自己创建的数据；清理失败导致非零退出，并保留诊断路径。报告输出文件独立于待清理库。

SQL WAL/FULL、原子文件保存、失败编辑保留、导入回执等待耐久写入、`.previous` 原件保护、关闭/导航前 flush 和 v5 白板协议保持不变。请求超时不代表事务回滚，功能检查根据实际结果确认恢复，避免重试重复写入。

## 验收与执行顺序

先测试报告统计、兼容比较与运行器数据隔离/失败退出，再完成存储 runner；之后完成可见桌面 runner 与离线回归；最后接入 npm 命令和说明。

新工具在有可用运行环境时执行并输出首份带身份信息的基线。运行器测试使用 Node 内置测试，不新增运行时依赖。真实存储模块需要当前 `npm run build:electron` 产物。

需要完成 `npm run check`、新增工具测试和适用的 Electron 回归。若依赖来自 Windows 且当前为 Linux，先记录原因并准备当前平台的开发依赖；源码检查结果与 Windows 原生验收结果分别记录。不得修改历史发行包或将本机生成的报告写为 beta.12 实际 exe 已验收。

第一阶段完成条件：工具、行为测试、离线回归与说明齐备；可运行的测量有当前报告；平台不可用的测量明确列为待目标机运行。性能改善幅度只有后续同环境前后比较才能宣称。
